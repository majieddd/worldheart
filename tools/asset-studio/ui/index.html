What each stage does
Concept starts with the main hero so you can inspect identity before spending on a reference pack. Test one generated angle before building the full pack. If it changes the character, choose Use exact model views: approve the hero, reconstruct and refine the model, then render six matching views and real walk frames before animation approval. Exact model views show the reconstruction; they do not independently prove hidden-surface accuracy. Generated views are proposals: reject changed costume, mirrored sides or inconsistent anatomy before approval. Shape uses the selected engine: Hunyuan multiview consumes four reviewed directional images; the mini and Trellis routes consume the hero only. Top and bottom remain inspection guides. Paint uses the original reference projection or locally generated Trellis.2 textures. Inspect seams and identity in either route. Rigging is required before animation: fit joints visually and save the model-specific profile, or prepare a MIA rig in Motion library. Motion preserves an imported rig or uses the fitted capture recipe. Generic sine-wave draft motion is not production output. The fitted Vey route replays surface repair, semantic paint, retargeting, wrist/digit fitting and sole checks. Other anatomies need a fitted profile before claiming the same quality. Inspect every clip before approving polish. The local pipeline never sends your prompts or assets to a paid generation API.
Automatic reconstruction and rigging need visual review, especially fingers, antlers, backs and unusual anatomy. A successful job is a candidate, not proof of production quality.

3D quality
Geometry grid is a 3D extraction resolution, not image pixels. Texture size supports 4096 px. Hunyuan steps stop at five minutes; 512 is experimental until measured on your asset. Multiview uses front, left, back and right; top/bottom remain inspection guides. Single-image engines use only the hero.
