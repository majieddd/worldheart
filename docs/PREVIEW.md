# Live V2 development workflow

The owner authorized this workflow on 2026-09-06 so development can be played
alongside the stable game without merging gameplay PRs into main.

| Route | Source | Purpose |
|---|---|---|
| [Original game](https://majieddd.github.io/worldheart/) | main | Stable game; preview publishes preserve its tracked file bytes |
| [V2 preview](https://majieddd.github.io/worldheart/v2/) | preview/v2 | Latest integrated, verified work; defaults to the saved 99-planet campaign |
| [Live build identity](https://majieddd.github.io/worldheart/v2/build.json) | Deployment artifact | Exact preview/main commits and preview asset hashes |
| /worldheart/dist/worldheart.html | main | Stable single-file download |

## Publish each working checkpoint

1. Read the tracker and fetch origin. Branch new campaign work from
   origin/preview/v2 so it includes the current preview and publishing workflow.
   Claim the issue, owner, branch and bounded subsystem before edits.
2. Implement a coherent change. Run syntax, relevant tests, house style and
   the necessary browser checks. Keep failures and remaining acceptance explicit.
3. Run node tools/deploy.mjs, update the progress ledger/blueprint, and commit
   source plus generated files. Push your feature branch and retain its PR.
4. Run node tools/publish-preview.mjs. It requires a clean checkout and advances
   preview/v2 by fast-forward only. If another collaborator published first,
   integrate origin/preview/v2 and recheck; never overwrite their work.
5. Check the Publish V2 preview action, then fetch /v2/build.json and confirm
   its previewSha matches the tested commit. Open /v2/, reload, and verify the
   changed behavior. Record the commit, deployment link, evidence and open gaps
   on tracker #1 and the relevant milestone.

The existing authorization covers these repeated preview publishes. It does not
authorize merging into main. Publish useful tested checkpoints during work,
rather than waiting for the whole milestone. A failed validation/deployment
leaves the last successful preview live. Refresh the page to load a new build;
an already running session is not replaced underneath the player.

## How the two routes stay separate

GitHub Pages uses the GitHub Actions publishing source. The workflow in
.github/workflows/preview-pages.yml checks out main and preview/v2 separately,
validates the preview and creates one combined artifact with tools/pages-site.mjs.
All public tracked main files except its old v2 mirror retain their bytes.
Only index.html, js, css and lib from preview source are installed under v2.
No feature code is copied to the stable root. The artifact includes .nojekyll
and a machine-readable build identity. No deploy branch or force push is needed.

The github-pages environment permits preview/v2 in addition to its existing
branches. Deployment concurrency serializes the whole build/deploy operation.
Only pushes to preview/v2 trigger preview publishing during the unmerged phase;
ordinary feature/PR pushes run review checks. The workflow also handles main
pushes once the workflow itself reaches main in a separately authorized release.
Until then, after an authorized production release, advance preview/v2 with the
release commit as well to republish the combined artifact. Main alone no longer
uses the former implicit branch-based Pages deployment.

The checked-in v2 directory is still generated by tools/deploy.mjs for local
testing and mirror checks. It is not the source selection mechanism for live
Pages. Stable dist remains from main; preview publication does not replace it.

## Saves and testing

V2 uses whV2-prefixed localStorage keys for campaign saves, talents, map/seed,
camera and motion settings. It starts with a separate profile and never silently
imports the original game's progress. V2 progress persists across ordinary
preview deployments; incompatible future changes need explicit migration.
Campaign export/import remains available for deliberate backup or transfer.

The bare V2 URL starts the saved 99-planet campaign for a fresh preview profile.
Explicit classic map links still work, for example /v2/?map=pocket.
Use /v2/?map=ninetynine&campaign=0 for the single-planet sandbox.

Deployment is not release acceptance. Ocean balance, full unforced 99-planet
completion, broader performance/accessibility and owner art/feel review remain
tracked in docs/PROGRESS.md and the M0-M6 issues.

## Recovery

For a broken preview, revert the offending change in a new commit on the current
integration history, verify it, then publish that commit normally. Never reset
or force-push preview/v2. For workflow repair, preserve the last successful
deployment while testing a corrected action. Pages can be returned to legacy
main-root publishing if necessary; doing so also restores main's old v2 mirror.
